## Shroudly 2.5.5

- **Roblox through Shroudly, installer included (Windows).** With Games and apps mode on, Settings now has **Open Roblox** and **Install Roblox**. Install downloads Roblox's own installer through Shroudly, checks that it is signed by Roblox Corporation and starts it; before, the installer stopped at *Continue installation without flag settings*. Bloxstrap and Fishstrap are started the same way.
- **Roblox no longer slips past Shroudly unnoticed (Windows).** Roblox started from a browser that was already open kept that browser's old settings and connected directly, so it stayed blocked. Shroudly now notices within a minute and offers to restart it through Shroudly.
- **Blocked sites stay on Shroudly.** When one connection to Shroudly failed, browsers used to go around it for five minutes, and blocked sites failed with no sign of why. Listed sites now always go through Shroudly. (On XFCE, LXQt and other Linux desktops without a proxy setting, browsers instead connect directly whenever Shroudly is not answering, so stopping or quitting it never leaves Chrome or apps like VS Code without internet.)
- **Networks that drop connections instead of refusing them.** Some providers do not reset a blocked connection, they simply never answer. Shroudly now keeps trying the other techniques there and remembers how far it got, so the next connection starts where the last one stopped. A site that answers nothing at all is reported in Logs, without a notification, since a site that is down looks exactly the same.
- **Connections cut while being sent.** On some networks the filter cuts a connection while Shroudly is still sending it. Shroudly gave up on that connection, so apps kept reconnecting and pages loaded half-way; it now moves on to the next technique.
- **Programs that are not browsers go through Shroudly too.** On Windows the automatic-proxy setting now offers the older SOCKS form as well as SOCKS5, so Java apps, Windows' own downloaders and .NET programs follow it instead of failing — one Java app was throwing an "unknown protocol: socket" error on every start-up. Thanks for the report.
- **Discord and Roblox at login.** With Discord app mode or Games and apps mode on, a program that connected in the seconds before protection was up (at login, or while the engine restarted) went out directly and was blocked, so Discord kept saying *retrying* and Roblox *failed to load critical settings*, sometimes and not others. Those connections now wait for protection instead. Thanks for the report in [#10](https://github.com/umutxyp/Shroudly/issues/10).
- **More ways past the filter.** Added the multi-cut techniques (the record split into several pieces at once, in order or out of order) that users on Türk Telekom and Turkcell have found work best, so the automatic search has them to try.
- **Advanced mode: QUIC forced to TCP.** Browsers try blocked sites over HTTP/3 (QUIC, which runs on UDP and never went through Shroudly's TCP proxy), so YouTube and Google could stay blocked even with Shroudly on. Advanced mode now drops the QUIC start packet, the same thing GoodbyeDPI and zapret do, so the browser falls back to TCP, which Shroudly handles. Non-blocked sites just lose QUIC's small speed-up and keep working. On by default; IPv4. This only helps where the network blocks QUIC — a site blocked by address still needs a VPN.
- **Advanced mode: decoy packets for Discord voice.** A filter can recognise the first packets of a Discord voice call (its IP-discovery and STUN requests) and block the call. Advanced mode now sends a few harmless decoy packets ahead of the first real ones so the filter's pattern-match is spoiled. On by default. It helps only where the **network** blocks those packets; if Discord's voice servers are blocked by address, voice still needs a VPN, and Shroudly says so rather than pretending to fix it.
- **One site, one lesson.** What works for a site is now used for all of its addresses at once (www., api., cdn. and the rest), instead of being found again for each one, so the parts of a site after the first open without the extra wait.
- **macOS: Standard (non-administrator) accounts.** macOS does not let them change network settings, so nothing went through Shroudly. The window now says so and asks for an administrator's password once; stopping needs no password. After a restart of the Mac, a dismissed password request is not repeated at every login: the window offers a button instead.
- **Linux: KDE Plasma, XFCE and LXQt.** KDE's own proxy setting is set. On XFCE and LXQt, which have no system proxy setting, Firefox goes through Shroudly at once and Chrome, Edge, Brave and other Chromium browsers after you log out and back in; a session that does not read the login settings (`startx`, a compositor started from a text console) is told the address to set by hand.
- **Told when another program takes over.** If a VPN or another proxy program changes the system proxy while Shroudly is on, the window says so, with a button to set Shroudly again.
- **A site that refuses you itself is explained.** Some services turn whole countries away on their own (HTTP 451, or a page saying the service is not available in your country or region). Shroudly never changes your address, so it cannot help there; the site test and the window now say so instead of suggesting another technique. A site that accepts the connection and then goes silent is reported with both possible causes, the site or the network, since the two look the same. This is judged from what the site does, the same way in every country.
- **Every address of a site is tried.** When a site has several servers and one does not answer, the next one is used.
- **Updates wait for your game.** An update no longer restarts Shroudly while a Roblox game or Discord goes through it (Games and apps mode, Discord app mode); it installs once they are closed. They cannot hold it back for good: after a few hours of waiting it also installs once the computer has been left alone for ten minutes or is locked, and on Windows and Linux at the next start, before protection comes on.
- **Linux desktops without a tray:** closing the window minimises it instead of leaving Shroudly running with no way back, Shroudly started at login or by an update comes up minimised instead of invisible, and Settings has a Quit button.
- Smaller things: programs that only speak SOCKS4 are served; Logs names the program that answers DNS on this computer when it can see it, and says when the system DNS answers nothing; a site that could not be reached at all is logged once with the reason.

Everything from [2.5.4](https://github.com/umutxyp/Shroudly/releases/tag/v2.5.4) is included. Users of 2.0.4 and later update automatically.
