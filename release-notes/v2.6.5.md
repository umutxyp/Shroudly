## Shroudly 2.6.5

**Your own DNS server (DoH, DoT, TCP or plain DNS), and a proxy left behind by another program no longer leaves apps stuck: Shroudly finds it and fixes what it can by itself.**

### Your own DNS server ([#34](https://github.com/umutxyp/Shroudly/issues/34))
- **New:** Settings → **DNS server** (desktop) and About → Settings → **DNS server** (Android). Keep **Automatic** (Shroudly's encrypted DNS, as before), or choose **DNS over HTTPS**, **DNS over TLS**, **DNS over TCP** or **plain DNS (UDP)** and type the server: `https://dns.google/dns-query`, `dns.quad9.net`, `1.1.1.1`, `8.8.8.8:53`…
- **DNS over TCP** helps where a network blocks or forges UDP port 53 but leaves TCP alone.
- The server is asked once before it is used, and the answer is shown (how fast, and the address it gave). A typo is caught with an example of what to type; a server that does not answer is used only if you press **Use anyway**.
- DoH and DoT go through Shroudly's engine like any site, and a server given by name is looked up over Shroudly's encrypted DNS, never your network's.
- If your server stops answering, Shroudly's encrypted DNS answers until it is back, so nothing stops loading; the log says so in one line. A change takes effect at once; nothing restarts.
- On Android, DNS over HTTPS speaks HTTP/1.1 (as Shroudly's own routes there): a server that accepts only HTTP/2 works there over DNS over TLS instead.

### A proxy left behind by another program
A proxy tool that is no longer running (ByeDPI, an old VPN or proxy app) can leave settings that point at it, such as `127.0.0.1:1080`. Everything sent there reaches nothing, with or without Shroudly: this is what kept Discord on **"Starting"** for some users. Shroudly now finds these and fixes what it can:
- **Discord Drover** (`version.dll` and `drover.ini` beside Discord) pointing at a proxy that is gone: Shroudly moves the two files into its own folder (nothing is deleted; a note there says how to put them back) and restarts Discord.
- **Windows' manual proxy** pointing at a program that is gone: switched off, its address kept (macOS and Linux already did this).
- **`HTTPS_PROXY` for programs** pointing at one: Shroudly's is used while Games and apps mode is on, and yours comes back when the mode goes off.
- **Windows' WinHTTP proxy** (`netsh winhttp`, used by Windows Update and the Microsoft Store) pointing at one: Shroudly says so and offers to clear it (Windows asks for an administrator).
- **Any other program** that sends everything to such a proxy (Windows): named in one line, with what to remove.
- **Android:** a Wi-Fi proxy on the phone where nothing runs is shown when you open the app, with a button to Wi-Fi settings (no app may change it). Turning **Proxy only** off while your Wi-Fi's proxy still points at it posts a reminder to set it back to None.

A proxy that is running is never touched.

### Discord and Roblox Studio
- A Discord that was already open when Shroudly started is looked at once, and restarted only if it really went around Shroudly.
- Windows: the setting programs read (`HTTPS_PROXY`) is announced to Explorer again shortly after login, so programs started from the Start menu or the taskbar (Roblox Studio among them, [#33](https://github.com/umutxyp/Shroudly/issues/33)) get it even when Windows missed the first announcement at login.

Everything from [2.6.4](https://github.com/umutxyp/Shroudly/releases/tag/v2.6.4) is included. Desktop users update automatically; the Android app tells you that 2.6.5 is out.
