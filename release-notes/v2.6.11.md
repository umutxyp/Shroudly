## Shroudly 2.6.11

**Programs that ignore the proxy (a Discord bot, a game launcher, a command-line tool) now get encrypted DNS too, in Advanced mode.**

### Encrypted DNS for every program (Advanced mode, Windows and Linux)
- A program that does not use the system proxy asks your network's DNS directly. On a network that blocks a site through DNS, it gets a forged address, reaches the block page and fails with a certificate error such as `ERR_TLS_CERT_ALTNAME_INVALID`. This happened to a Discord bot on Node.js, even with `1.1.1.1` set in Windows, because the network forges plain DNS answers whichever server is asked.
- In Advanced mode with **DNS anti-poisoning** on, Shroudly now answers every program's plain DNS questions (UDP port 53) itself. The answer comes from Shroudly's encrypted DNS, or from the DNS server you chose in Settings, as if from the server the program asked. Together with Advanced mode's packet-level techniques, such a program now reaches the site.
- Only a public address, or "no such record", is answered this way. If encrypted DNS does not know the name (an intranet, a VPN's own names), gives only a private address, or does not answer in time, the question goes on to its own server unchanged. Local names and company networks keep working.
- Windows: IPv4 and IPv6. Linux: IPv4. It is checked on a real packet path in both test labs, both for a program asking a DNS server itself and for the system's resolver.
- Shroudly's encrypted DNS keeps its local port when protection is stopped and started again, so Advanced mode keeps reaching it.

Everything from [2.6.10](https://github.com/umutxyp/Shroudly/releases/tag/v2.6.10) is included. Desktop users update automatically; the Android app tells you that 2.6.11 is out.
