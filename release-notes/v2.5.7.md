## Shroudly 2.5.7

- **No more false "blocked" and "cut" warnings for sites that work.** Several people saw warnings for sites that were never blocked: *af.opera.com could not be opened with any technique* (a background address of the Opera browser) and *ws.chatgpt.com connects, then the network cuts it* (ChatGPT's live connection) while the sites themselves worked. Shroudly now tells these apart from a real block:
  - A live connection (a WebSocket, a long-poll) that has been answered is no longer watched for cuts. Its later silence, or its server closing it when idle, is how such connections work, not a filter.
  - When the rest of a site works through Shroudly and only one of its other addresses does not answer, that is a line in Logs, not a warning. A site's own page (example.com, www.example.com) is still always reported.
  - When the server itself turns the connection down (a TLS alert to the unchanged request), that is not reported as a block either.
  - None of this changes how sites are opened; it only changes what is reported.
- **Hide the icon in the notification area** ([#12](https://github.com/umutxyp/Shroudly/issues/12)). Settings now has *Show icon in the notification area*. Turned off, Shroudly keeps running in the background with no icon (none in the menu bar on macOS either); start Shroudly again (Start menu, Applications) to open its window. Settings has a Quit button for when you want it to stop.

Everything from [2.5.6](https://github.com/umutxyp/Shroudly/releases/tag/v2.5.6) is included. Users of 2.0.4 and later update automatically.
