## Shroudly 2.3.0

The release that answers the reports from the last few days. Three things were wrong, and all three are fixed.

### A blocked site no longer fails on the first try
Two separate causes, both gone:
- **DNS was slow enough to look broken.** Shroudly asked its encrypted resolvers one after another, so a single slow one cost four seconds and the lookup fell back to ordinary DNS — the very thing a censor tampers with. Resolvers are now asked in parallel over connections that are opened at startup and kept open, and answers are cached. First lookup: **229 ms instead of a timeout.** Repeat lookups: **under 1 ms.**
- **A refused connection reached the browser as an error.** Now, when a connection is cut, Shroudly reconnects and tries another technique without the browser ever seeing it. Tested against a server that kills the first two attempts: the page still loads, in 6 ms, with no error.

### It gets past filters that beat the old method
Splitting a connection is not enough against providers that reassemble it first — **Turkcell Superonline and Turkcell mobile** do exactly that. Shroudly now also:
- re-frames the handshake into two TLS records, which defeats reassembly and works identically on every system,
- delivers the two halves genuinely out of order,
- can place an out-of-band byte inside the site name,
- and combines these the way they need to be combined.

It tries them in order until one works, then remembers it for that site. A fake "blocked" page is no longer mistaken for success.

### Nothing is slowed down
Shroudly now leaves a connection completely alone unless it is actually refused. Ordinary browsing is relayed untouched — **0.26 s through Shroudly against 0.246 s with it off.** Because of that, everything can safely go through it by default, which means a blocked site works **without you having to add it to any list first**, and every lookup gets encrypted DNS. You can still narrow it to a list of sites in Settings.

### Also in this release
- A short introduction the first time you open the app, in all fifteen languages.
- The built-in site list now covers the widely blocked services **together with the CDN domains they load images and video from**, so a site never loads half-broken.
- The log now records what Shroudly actually did — your system, your network, and for each site the technique that worked or how many were tried. If you report a problem, that log is usually enough to answer it.
- If another bypass tool or VPN is running, Shroudly says so: two of them steering the same connections is the usual reason a working setup stops working.
- If your provider is caught returning forged DNS answers, encrypted DNS is switched back on automatically.

> **Discord voice** uses UDP, which never goes through a proxy like Shroudly's — whether it is on or off. Text, images and the web app work normally.
