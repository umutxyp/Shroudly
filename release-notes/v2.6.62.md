## Shroudly 2.6.62

**Tor is not thrown away by a quick Stop and Start, and helping others is no longer offered where Tor itself is blocked.**

### The last way out (Tor): kept through a quick Stop and Start
- Getting through to Tor can take minutes on a network that blocks it (Snowflake first, then meek and obfs4). Stopping protection stopped Tor with it, so a Stop and Start a moment later began again from nothing: an Iranian report showed it back at 10%. Now Tor is kept for five minutes after protection stops; a start within them goes on with the same Tor, on the same port, where it was. Off for longer, Tor stops. On computers and Android; on the Apple app Tor lives in the VPN's own process, which iOS and macOS end with protection.

### A site the network keeps cutting once open: Tor, sooner
- In Iran WhatsApp and Instagram open with a technique, then the network cuts them a few seconds later, again and again ("it connects, then disconnects"). Shroudly tried another technique for the next connection, but never the last way out, since none had failed outright. Now, once the network has cut the same name three times in ten minutes while nothing of that site gets through at all, its next connections go to Tor first (asked first, as always, if Tor was never allowed). A site whose other connections are answered is not counted: some servers hold a request open on purpose, and that is no block. Computers and Android.

### Helping others: not where Tor itself is blocked
- In Belarus, China, Iran, Myanmar, Russia and Turkmenistan Tor itself is blocked: the user there is among the people who need the help, and a Snowflake proxy there could not reach those it would help. "Help people in censored countries" is no longer shown there at all (the Snowflake switch, the main screen's row on Android, the section on the Apple app), and one left on from before does not run. The card asking for help was already not shown there.

### Android: a Stop always ends
- With Wi-Fi and mobile data trading places quickly, renewing the VPN interface could find the tunnel's old part not stopping; Shroudly then started the new one anyway, which waited on the old one for ever, and every later action with it: protection stayed at "stopping" and could not be turned off (a Turkcell report). Now a tunnel that does not stop ends protection cleanly, and, whatever holds it up, a Stop not through within 15 seconds ends the app's process, and the VPN with it.

### Games and apps mode: programs started meanwhile (issue #80)
- Programs started while the mode was on get Shroudly's program proxy in their environment, and Windows never takes it out of a program that runs. When Shroudly quit, such a program (Steam, the Epic Games Launcher) went on trying the address until it was restarted, and looked like Shroudly had broken the internet. Now Shroudly notes which programs used that address, and when it quits or the mode goes off, names the ones still running in one notification, to be restarted.

### Reports sent after a stop
- Most reports are sent once protection is off ("it does not work": off, then the report), and then said nothing of what had gone through. The last session's connections are now kept in memory until the next start, and such a report carries them, with when that session ended. Computers and Android. Android: in Proxy only with no app using it, the main screen now says that YouTube and other apps open as without Shroudly, with **Use VPN mode** a tap away.
