## Shroudly 2.4.1

### Arch, Manjaro and Fedora now get a proper package
Until now Linux meant a `.deb` or an AppImage, which left Arch and Fedora users with no native option. This release adds:

- **`.pacman`** — Arch, Manjaro, EndeavourOS, Garuda
- **`.rpm`** — Fedora, openSUSE, RHEL and derivatives

The AppImage still works everywhere and needs no installation.

### Security hardening
An audit of the previous release found several things worth closing, independently of anything being exploited:

- **DNS answers are now properly verified.** The engine checked that a reply came from the right address, but not from the right port, and never checked that the reply answered the question it had asked. The lookup socket is also bound to its resolver now, so the operating system discards anything from anywhere else before it reaches us — including from another program on your own machine. The identifier each query carries is drawn from the system's random source rather than derived from the clock, so it cannot be guessed.
- **On Windows, another program could take over Shroudly's local port.** The option used to reuse an address means something different on Windows than elsewhere: it allows a second process to bind the same port and receive the connections. The port is now reserved exclusively.
- **If encrypted DNS cannot be reached, Shroudly says so.** Blocking three addresses was enough to push every lookup back to ordinary DNS silently — the exact thing this feature exists to prevent. It still falls back, because a lookup that fails outright is worse, but it no longer does it quietly.
- The interface is now restricted to the content shipped inside the app, so nothing in it can send anything anywhere, and host names can no longer disturb the records the app writes.

Everything from [2.4.0](https://github.com/umutxyp/Shroudly/releases/tag/v2.4.0) is included. Users of 2.0.4 and later update automatically.
